# Habit Atlas Android Build Guide

Habit Atlas uses **Capacitor** because it packages the compiled, offline application with Android capabilities while preserving one local-first TypeScript domain model. The shipped Android app contains the web bundle; it does not depend on a remote page or a hosted habit API. Habit data continues to live locally in the application’s WebView IndexedDB store, and Android-specific hooks are limited to local notifications, deep links, sharing, haptics, and widget snapshots.

| Item | Current configuration |
|---|---|
| Package ID | `com.habitatlas.app` |
| App name | Habit Atlas |
| Android target | Generated by Capacitor/Android Gradle plugin |
| Web bundle | `dist/public` compiled into the Android project |
| Local database | IndexedDB via Dexie, no cloud database |
| Notification model | User-granted local Android notifications through Capacitor |
| Deep-link scheme | `habitatlas://` reserved for habit and widget actions |
| Store artifact | Android App Bundle (`.aab`) |
| Direct install artifact | Debug/release APK (`.apk`) |

## Local data and Android reliability

The web application uses IndexedDB rather than `localStorage`; Capacitor’s Android WebView provides a persistent app-private browser storage area. The UI bundle is stored in the installed application, and operations remain available in airplane mode. The native bridge is used only for device services—never to send habit data to a server.

## Native widget strategy

Android widgets are native `AppWidgetProvider` components. Their lightweight snapshot is intentionally separate from the authoritative IndexedDB database: the web app supplies a minimal, current **today snapshot** (habit ID, label, progress, and color) to the native layer after a user mutation; Android reads that snapshot to render the **Today**, **Progress**, **Streak**, **Heatmap**, and **Quick Complete** widget variants. Widget actions launch deep links back into the local app; they do not call a remote server. The scaffold added with this project includes the native provider and layout registration points; wire the snapshot bridge before releasing a widget-enabled production build.

## First-time Android setup

Install a compatible Android SDK and set `ANDROID_HOME`. The repository uses the Gradle wrapper generated by Capacitor, so Android Studio is optional for command-line builds but recommended for emulator testing, signing, and inspecting widgets.

```bash
pnpm install
pnpm run android:sync
cd android
./gradlew assembleDebug
```

The debug APK is normally emitted under `android/app/build/outputs/apk/debug/app-debug.apk`.

## Release AAB and signing

1. Create a private upload key. Never commit its keystore or passwords.
2. Put only local release variables in `android/keystore.properties` (ignored by Git).
3. Configure the `release` signing block in `android/app/build.gradle` to read those properties.
4. Run `pnpm run android:release`.
5. Upload the produced `android/app/build/outputs/bundle/release/app-release.aab` to the Google Play Console.

```bash
keytool -genkeypair -v -keystore habit-atlas-upload.keystore -alias habit-atlas -keyalg RSA -keysize 2048 -validity 10000
pnpm run android:release
```

Use an `.aab` for Play Store distribution. Use an APK only for direct test installation. Android release output cannot be installed from a browser without allowing installs from that source.

## Play Store preparation

The Play listing should explain that the app is offline-first, stores habit data locally, has no advertising SDK, has no behavioral analytics SDK, and requires notification permission only if the user turns on reminders. Prepare real screenshots from a populated local test database; do not use invented testimonials, ratings, or claims. Add an independently hosted privacy policy before submission that matches the actual data behavior.

## Current limitations requiring device QA

The application’s web/PWA flows are tested in-browser. The final APK/AAB must be built and smoke-tested using an Android SDK or Android Studio because that toolchain is not bundled in this workspace. Test fresh install, restart, airplane mode, notification denied/granted, back navigation, deep links, widget refresh, export/share, dark mode, and an upgrade from an existing local database before Play submission.
